# omicsApp — Visual Mock v0.1

Static HTML/SCSS preview of the omicsApp UI. No build step, no internet required: just open `index.html` in any modern browser.

## How to view

```bash
open mockup/index.html
# or, in RStudio:
#   File -> Open File -> mockup/index.html
#   then click "Show in new window"
```

## What's in here

| File | Purpose |
|---|---|
| `index.html` | Self-contained mock: 7 views with inline CSS + JS-rendered SVG plots |
| `styles.scss` | Design-token source. Phase 2 moves this to `packages/omicsApp/inst/app/www/styles.scss` and compiles via bslib |
| `README.md` | This file |

## Views covered

Click items in the left sidebar to switch.

- ✅ **Project** — overview cards, experiments table, recent activity
- ✅ **Import** — 3-step wizard, inferred schema review with confidence bars, validation warnings
- ✅ **Quality Control** — sample/feature stats, PCA, missingness pattern (samples × features)
- ✅ **Differential** — parameter sidebar, volcano (interactive-style), top-hits table
- ✅ **Enrichment** — ORA/GSEA/GSVA tabs, dotplot, pathway table
- ✅ **Integration** — dual mirrored volcano, RNA × Protein scatter with quadrants, shared pathway dotplot, ActivePathways combined-p table
- ⬚ **Report** — placeholder card (Phase 4)

## Design system

### Color tokens

| Token | Hex | Use |
|---|---|---|
| `--brand-600` | `#2C3E99` | Primary actions, navigation active state, "down" semantic |
| `--accent-500` | `#1FBF9E` | RNA-seq layer indicator, success / "ready" |
| `--omics-up` | `#C0392B` | Up-regulated features (volcano dots, pills, NES) |
| `--omics-down` | `#2C3E99` | Down-regulated features |
| `--omics-ns` | `#9AA3AE` | Not significant (volcano background) |
| `#8E44AD` | — | Proteomics layer indicator (purple) |
| `#F59E0B` | — | Warnings, discordant integration |
| `#10B981` | — | QC pass, "imputed" cells |

### Typography

- **UI**: Inter (system-ui fallback), 13.5 px base
- **Numbers / IDs**: JetBrains Mono — used in stat values, log2FC / padj cells, sample IDs
- **Headings**: Inter 600, tight letter-spacing (-0.01em)

### Density

- Card padding: 18-20 px
- Table row: 8 px vertical (compact, scannable)
- Component radius: 8 px (md) for cards/inputs, 12 px (lg) for prominent containers, 999 px for pills
- Sidebar width: 232 px

### Plotting

All plots in the mock are inline SVG, generated by JS from deterministic PRNG seeds so the layout is stable across reloads. Phase 2 replaces these with:

- **Volcano / scatter / PCA**: `ggplot2` → `plotly::ggplotly()` for hover + lasso
- **Heatmap**: `ComplexHeatmap` → static (rasterized) for performance; interactive feature highlight via Shiny inputs
- **Dotplot**: `ggplot2` → `ggplotly`

## Mapping to bslib

The mock uses pure CSS but is structured to translate cleanly to `bslib::page_navbar()` + `bslib::card()`:

| Mock element | bslib equivalent |
|---|---|
| `.app-shell` grid | `page_sidebar()` or custom `page_fluid()` with grid |
| `.app-sidebar` | `sidebar()` |
| `.app-header` | `card_header()` slot on a top-level container |
| `.card` | `card(card_header(), card_body())` |
| `.stat-card` | `value_box()` (bslib 0.5+) |
| `.tabs` | `navset_pill()` |
| `.btn-primary` | `actionButton(class = "btn-primary")` |

Phase 2 will codify the Sass overrides in `R/app_theme.R`.

## Open questions for review

Things to look at and tell me what to change:

1. **Density** — too tight, too loose, or right?
2. **Color** — is the purple/teal split for proteomics/RNA distinct enough? Should "up" be red, or use the journal's preferred (e.g. orange)?
3. **Sidebar** — dark sidebar vs. light? Icons-only collapse needed?
4. **Stat cards on top** — 4 always, or fewer? Useful info or noise?
5. **Volcano / scatter density** — too many points, too few? Need a "density mode" for very large datasets?
6. **Integration view** — does the 4-panel layout read as one coherent story, or should it split across tabs?
7. **Project picker** — should it be the dominant left thing (above sidebar nav) instead of in the header?

## What's NOT in this mock

- No real interactivity beyond view-switching / tab-switching
- No empty / loading / error states (Phase 2 deliverable)
- No mobile layout (desktop ≥1280 px target; web tool is a desktop product)
- No dark mode (planned for Phase 4 polish)
