## 1. 准确性

### 已验证正确（摘要）
- limma：两组、多组共享拟合、两两比较、`(B+C)/2 - A` 自定义对比、协变量、连续变量（线性/样条）、ANOVA，与直接调用一致（≤ 7e-14）。
- edgeR QL 全流程（含 ANOVA）完全一致；被检验的基因恰为 `filterByExpr` 保留集，NA 行恰为被过滤基因。
- DESeq2：Wald、多组、协变量、配对、LRT、连续变量一致；baseMean 误差 ≤ 1e-6。
- t 检验、lm 与 `t.test` / `lm` 完全一致；所有方法中 effect > 0 均表示处理组更高。
- 校准：limma（非配对）、t 检验、lm、edgeR、所有 ANOVA、连续变量检验在零假设下假阳性率 ≈ 名义水平；所有真阳性方向正确。
- ORA 与手工超几何检验 + BH 完全一致；GSEA 与 `clusterProfiler::GSEA` 完全一致；GSVA、vsn、相关性整合、concordance（Fisher 合并 p）、ActivePathways 均一致。

### 发现并修复
| 级别 | 问题 | 修复 |
|---|---|---|
| **高** | **配对 limma 假阳性偏多**：用 `duplicateCorrelation` 假设所有特征共享同一个对内相关；真实数据中相关性因特征而异，零假设下 p<0.01 的比例为 1.8%（应为 1%），n=4 对时实际 FDR 0.46（名义 0.05）。这是配对蛋白组的默认路径 | 只要每个配对至少 2 个样本且设计满秩，就把配对作为**固定效应区组**（limma 用户指南推荐做法）；结果与参考实现完全一致（0.00975 vs 0.00975，零误报）。只有在个体水平协变量（如性别）等必须用随机效应时才回退，并在结果中说明 |
| 中 | edgeR 使用 tximport 基因长度时跳过 TMM，10% 基因上调 8 倍会使 1449/1774 个未变化基因被判为"下调" | 改为 tximport 官方流程（长度因子 + TMM），未变化基因误报 13/1774，与不用长度时相同 |
| 中 | GSVA 遇到缺失值：一个 NA 让整条通路在所有样本中都成为 NA | 含缺失的特征排除并说明数量，建议先在 QC 插补 |
| 中 | limma ANOVA 只有两个组时报错 "Column `F` not found" | 单系数时 F = t²，结果与两组比较完全一致 |
| 中 | 配对 t 检验的效应量用了所有样本的均值，可能与检验方向相反（effect −3.1 标为 down，而 t = +12） | 效应量改为完整配对的平均差 |
| 低/中 | 对 ANOVA / 样条结果做 GSEA 或分方向 ORA 没有意义（无方向） | 直接拒绝并说明原因 |
| 低/中 | 原始计数转 log2(CPM+0.5)，20M 深度下相当于加 10 个 reads，低丰度基因倍数被明显压缩（真实 log2FC=1 估成 0.42–0.74） | 改为 voom 的 log-CPM 公式 |
| 低 | 连续变量结果中 effect 取 Spearman ρ 而 p 来自斜率，9% 特征符号相反，GSEA 排序随之颠倒 | GSEA 排序直接使用检验统计量本身的符号 |
| 低 | 文档与实际不符：`impute_matrix(method = "min")`、`normalize_omics(offset)` | 文档已更正 |

UI 审查还发现一个**准确性层面的高危 bug**：自定义对比只要没有涉及所有组（如三组中写 `TreatA - Control`），就必定报内部错误。已修复（权重只赋给参与拟合的组），并补测试。

**未修复，列入下一版：** 小样本（n≈12）时基于 z 分数的离群检测几乎检不出明显离群样本，需要稳健方法（中位数/MAD 或 PcaHubert），但要注意组间不平衡带来的假阳性，需单独设计。DESeq2 本身在模拟中略偏宽松（FDR 0.09–0.15，edgeR 为 0.05–0.07）——这是 DESeq2 的特性，软件忠实复现；可考虑计数数据默认改用 edgeR，留待下版讨论。

## 3. 代码执行效率

规模：蛋白组 8,000×60 / 8,000×300（含 16% 缺失），RNA-seq 30,000×60 / 60,000×300；单线程计时（与生产容器一致），
全部测量 481 行。每项优化都与原实现在同一进程中 A/B 计时，并用 `all.equal`（1e-8）核对输出**完全一致**后才采用。

### 已采用的优化
| 用户看到的问题 | 根因 | 修复 | 前 → 后 |
|---|---|---|---|
| QC 视图每动一次滑块都冻结整个会话（8k×300 拖动 5 格 61.6 s） | 主进程同步运行、无防抖；每次重算 TMM 和两次 PCA；成对相关逐对计算 | 滑块防抖 400 ms；TMM 因子按矩阵内容缓存；PCA 按内容缓存（QC 检测与 PCA 图共用）；成对完整相关改为矩阵乘法 | 拖动 **61.6 → 3.4 s**（RNA 30k：29.6 → 1.2 s）；打开视图 15.0 → 3.9 s；连通性检测 7.9 → 0.2 s |
| lm 后端：8k 蛋白 3 个对比 33 s，30k 基因 292 s | 每个特征一次 `lm()` + `summary()` | 按缺失模式共享 QR 的批量最小二乘 | 33.3 → **3.7 s**（无缺失时 0.14 s）；30k 两组 38 → 1.3 s |
| 连续变量（limma）8k 需 9 s、30k 需 42–113 s；**且遇到全缺失的蛋白直接报错** | 两个逐特征 `apply(lm/cor.test)` | 同上批量计算 + 行内 Spearman；缺失特征给 NA | 8.9 → **0.9 s**，30k 42.5 → 2.6 s；不再报错 |
| t 检验：两两比较 8k 6.4 s、30k 26 s | 每个特征一次 `t.test()` | 向量化 Welch / 等方差 / 配对 | 6.4 → **0.36 s**；30k 25.9 → 2.6 s |
| 每个差异结果都带着 DESeq2/edgeR 模型对象（56–314 MB），每次自动保存都写一遍 | 结果包保存了无人读取的模型对象 | 计数模型对象不再保存（需要时 `options(omicsCore.keep_count_models = TRUE)`） | 60k×300 结果包 **316 → 15.7 MB**；整个项目 68.7 → 17.5 MB |
| 3–6 万点的火山图在浏览器中首次绘制 4 s、悬停卡顿 | SVG 每点一个节点 | `toWebGL()` | 60k 点 **4.0–4.4 → 0.47 s**，数据与悬停文字不变 |
| 60k×300 的 xlsx 导入峰值内存 8.2 GB，会被 6 GB 容器杀掉 | readxl 约需解压后大小的 16 倍内存 | 生产镜像把工作簿解压上限设为 300 MB，超过时提示改用 CSV（同样数据约 1 GB） | 不再 OOM |

### 未采用 / 留待下一版
- DESeq2 并行（BiocParallel，2 核 19.8 → 15.0 s）：容器只有 2 核且已有 2 个后台 worker，收益有限，暂不默认开启。
- 自动保存节流：模型对象移除后单次写入已从数秒降到亚秒级，暂不改动保存时机。
- go_bp 的基因集表每次富集都重建（约 1 s / 400 MB），compare_enrichment 时重复 3 次——可缓存。
- CSV 读取用 `read.table`（35 MB 需 8 s，`data.table::fread` 0.06 s）——引入 data.table 需权衡依赖。
- 60k×300 规模下 DESeq2 约 2.5 分钟、edgeR 多组约 100 s：属于算法本身耗时，需要进度细分（下一版）。
